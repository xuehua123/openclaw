# 06. 安全与风险评估

## 风险面总览
- 供应链风险：第三方插件、脚本、镜像、面板引入不受控代码。
- 凭据风险：模型 key、IM token、Webhook 密钥泄露。
- 通道风险：多 IM 渠道接入导致攻击面扩大。
- 指令注入：Prompt injection / tool abuse 触发越权操作。
- 主机风险：部署机权限过大、日志泄露、容器逃逸配置不当。

## 部署安全基线（建议）
1. OpenClaw 与数据库/缓存/面板分离网络与最小权限运行。
2. 所有密钥使用环境变量或密钥管理服务，不写入仓库。
3. 插件采用白名单策略，默认禁用高危执行类工具。
4. 关键动作引入人工确认门槛（支付、删库、批量外发）。
5. 对外 Webhook 开启签名校验与速率限制。
6. 对日志进行脱敏，避免写出明文 token/PII。

## 插件/技能引入前审查单
- 是否有明确 License。
- 是否有活跃维护记录。
- 是否存在 `curl | bash` / 远程动态下载执行。
- 是否要求长期高权限 token。
- 是否能在隔离环境先行验证。

## 建议的安全落地流程
1. 建立插件分级：`可直接启用` / `需审计` / `禁止`。
2. 先在测试网关验证，再灰度到生产网关。
3. 每次升级后复测关键用例：授权、审计、回滚。
